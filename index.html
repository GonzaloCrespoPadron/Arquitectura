Arquitectura de automatización asistida por IA

1. Funcionamiento de la IA y relación con el repositorio

Copilot ayuda a desarrollar y mantener las herramientas; las aplicaciones ejecutan los procesos empresariales.

flowchart LR
    U[Desarrollador] --> O[Agente orquestador]
    O --> CTX[Consulta contexto]
    CTX --> INS[Instrucciones .github]
    CTX --> REP[Repositorio]
    CTX --> MEM[Memoria relevante]
    CTX --> DOC[Documentación]
    O --> SEL[Analiza requerimiento y selecciona agente]
    SEL --> AC[Agente C# / AutoCAD]
    SEL --> AL[Agente AutoLISP]
    SEL --> EV[Agente Excel / VBA]
    SEL --> AP[Agente Python]
    SEL --> QA[Agente QA]
    subgraph R[Componentes del repositorio]
      CAD[Plugins AutoCAD]
      LISP[Rutinas AutoLISP]
      EXCEL[Macros y herramientas Excel]
      PYTHON[Aplicaciones Python]
      LIB[Bibliotecas compartidas]
      TEST[Pruebas y validaciones]
    end
    AC --> CAD
    AC --> LIB
    AC --> TEST
    AL --> LISP
    AL --> TEST
    EV --> EXCEL
    EV --> LIB
    EV --> TEST
    AP --> PYTHON
    AP --> LIB
    AP --> TEST
    QA --> TEST
    QA --> CAD
    QA --> LISP
    QA --> EXCEL
    QA --> PYTHON
    CAD --> RES[Resultados del desarrollo]
    LISP --> RES
    EXCEL --> RES
    PYTHON --> RES
    TEST --> RES
    RES --> REV[Revisión humana]
    REV --> GH[Pull Request e integración en GitHub]
La IA no sustituye las reglas técnicas: ayuda a crear código, pruebas y documentación. El software versionado realiza los cálculos y automatizaciones.

2. Organización del repositorio

Un repositorio corporativo puede contener aplicaciones independientes, reglas comunes, bibliotecas reutilizables y validaciones.

    G --> APPS[apps]

    G --> DOCS[docs]

    G --> VSCODE[.vscode]

    subgraph APPLICATIONS[Aplicaciones independientes]

      UTILS[Utilidades comunes]

    subgraph VALIDATION[Pruebas y validaciones]

      INT[Integración]

      DEC[Decisiones técnicas]

    end
    subgraph MEMORIES[Memoria del proyecto]
      GLOBAL[Memoria técnica general]
      DOMAINMEM[Memoria por dominio]

    CAD --> DOMAIN
    XLS --> DOMAIN
    PY --> DOMAIN
    CAD --> TESTS
    XLS --> TESTS
    LIS --> TESTS
    PY --> TESTS
    CI --> AG
    AG --> IN
    IN --> PR
Compartir repositorio no obliga a conectar técnicamente las aplicaciones. Una macro Excel puede permanecer independiente de AutoCAD y Python.

3. Organización de la memoria

La memoria conserva el estado de cada aplicación y, cuando corresponde, resume conocimiento técnico reutilizable.

flowchart LR
    M[Memoria del proyecto] --> G[Memoria global]
    M --> D[Memoria por dominio]
    M --> A[Memoria por aplicación]
    M --> H[Historial y estado]
    subgraph GLOBALMEM[Memoria técnica general]
      GC[Patrones reutilizables]
      GR[Reglas comunes]
      GV[Validaciones comunes]
      GG[Glosario]
    end
    subgraph DOMAINMEM[Memoria por dominio]
      DA[AutoCAD]
      DE[Excel y VBA]
      DL[AutoLISP]
      DP[Python]
      DC[C#]
      DEL[Reglas eléctricas]
    end
    subgraph APPMEM[Memoria específica de cada aplicación]
      AS[Estado actual]
      AF[Funcionalidades]
      APEND[Pendientes]
      AD[Dependencias]
      AE[Errores conocidos]
      AV[Versiones compatibles]
    end
    subgraph HISTORY[Historial y documentación]
      CH[CHANGELOG.md]
      DEC[Decisiones técnicas]
      LOG[Logs de ejecución]
      TEST[Resultados de pruebas]
    end
    DEV[Desarrollo o actualización] --> AS
    DEV --> CH
    DEV --> DEC
    DEV --> TEST
    AS --> CONT[Contexto para futuras versiones]
    CH --> CONT
    DEC --> CONT
    TEST --> CONT
    CONT --> REU{¿Conocimiento reutilizable?}
    REU -->|Sí| GC
    REU -->|Sí| GR
    REU -->|No| KEEP[Permanece en la aplicación]
    AS --> KEEP
    KEEP --> CONT
    D --> LOAD[Carga selectiva según la tarea]
    A --> LOAD
    G --> LOAD
El estado, historial y decisiones de una aplicación se conservan para futuras versiones. Solo los patrones generales se resumen además en la memoria técnica global.

4. Flujo integrado completo

Desde un requerimiento hasta la integración en GitHub y la actualización de la memoria del desarrollo.

flowchart LR
    R[Requerimiento] --> C[Copilot recibe solicitud]
    subgraph CONTEXTO[1. Recuperación de contexto]
      C --> I[Lee instrucciones generales]
      I --> RP[Analiza repositorio]
      RP --> RA[Revisa aplicaciones existentes]
      RA --> RC[Revisa código y pruebas]
      RC --> RD[Revisa documentación]
      RD --> RM[Recupera memoria relevante]
      RM --> RS[Lee estado de la aplicación]
    end
    subgraph ANALISIS[2. Análisis y decisión]
      RS --> A[Analiza objetivo y restricciones]
      A --> T[Identifica tipo de desarrollo]
      T --> TEC[Propone tecnología]
      TEC --> AG[Selecciona agente especialista]
      AG --> ALC[Define alcance, archivos y pruebas]
      ALC --> CONF{¿Usuario confirma?}
    end
    CONF -->|No| AJ[Ajustar requerimiento o alcance]
    AJ --> A
    CONF -->|Sí| RAMA[Crear rama de trabajo]
    subgraph ESTRUCTURA[3. Preparación]
      RAMA --> NUEVO{¿Nueva aplicación?}
      NUEVO -->|Sí| UB[Determinar ubicación]
      UB --> CARP[Crear carpeta y estructura estándar]
      CARP --> BASE[Crear README, memoria y pruebas base]
      NUEVO -->|No| EXIST[Conservar estructura existente]
    end
    BASE --> DES
    EXIST --> DES
    subgraph DESARROLLO[4. Implementación]
      DES[Agente especialista trabaja]
      DES --> COD[Crear o modificar código]
      COD --> COMP[Usar bibliotecas compartidas si corresponde]
      COMP --> TEST[Crear o actualizar pruebas]
      TEST --> VAL[Ejecutar pruebas y validaciones]
    end
    VAL --> OK{¿Resultados correctos?}
    OK -->|No| ERROR[Analizar errores y corregir]
    ERROR --> COD
    OK -->|Sí| REV[Revisión humana]
    REV --> APROB{¿Cambio aprobado?}
    APROB -->|No| OBS[Registrar observaciones]
    OBS --> COD
    APROB -->|Sí| VERSION[Actualizar versión y CHANGELOG]
    subgraph MEMORIA[5. Registro del desarrollo]
      VERSION --> EST[Actualizar estado de la aplicación]
      EST --> FUNC[Registrar funcionalidades]
      FUNC --> PEND[Registrar pendientes]
      PEND --> DEP[Registrar dependencias y compatibilidad]
      DEP --> INC[Registrar errores conocidos]
      INC --> PRUEBAS[Registrar pruebas realizadas]
      PRUEBAS --> DECIDE{¿Conocimiento reutilizable?}
    end
    DECIDE -->|No| LOCAL[Conservar información en la aplicación]
    DECIDE -->|Sí| TECNICA[Resumir en memoria técnica general]
    LOCAL --> PR[Crear Pull Request]
    TECNICA --> PR
    PR --> REVIEW[Revisión del equipo]
    REVIEW --> MERGE[Integrar en rama principal]
    MERGE --> FUTURO[Aplicación lista para futuras actualizaciones]
La memoria de la aplicación se actualiza siempre al terminar un desarrollo. La memoria técnica general recibe únicamente conocimiento que pueda servir a otras herramientas o proyectos.
