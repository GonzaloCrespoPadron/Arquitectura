3. Organización de la memoria

La memoria conserva el estado de cada aplicación y, cuando corresponde, resume conocimiento técnico reutilizable.

flowchart LR
    M[Memoria del proyecto] --> G[Memoria global]
    M --> D[Memoria por dominio]
    M --> A[Memoria por aplicación]
    M --> H[Historial y estado]
    subgraph GLOBALMEM[Memoria técnica general]
      GC[Patrones reutilizables]
      GR[Reglas comunes]
      GV[Validaciones comunes]
      GG[Glosario]
    end
    subgraph DOMAINMEM[Memoria por dominio]
      DA[AutoCAD]
      DE[Excel y VBA]
      DL[AutoLISP]
      DP[Python]
      DC[C#]
      DEL[Reglas eléctricas]
    end
    subgraph APPMEM[Memoria específica de cada aplicación]
      AS[Estado actual]
      AF[Funcionalidades]
      APEND[Pendientes]
      AD[Dependencias]
      AE[Errores conocidos]
      AV[Versiones compatibles]
    end
    subgraph HISTORY[Historial y documentación]
      CH[CHANGELOG.md]
      DEC[Decisiones técnicas]
      LOG[Logs de ejecución]
      TEST[Resultados de pruebas]
    end
    DEV[Desarrollo o actualización] --> AS
    DEV --> CH
    DEV --> DEC
    DEV --> TEST
    AS --> CONT[Contexto para futuras versiones]
    CH --> CONT
    DEC --> CONT
    TEST --> CONT
    CONT --> REU{¿Conocimiento reutilizable?}
    REU -->|Sí| GC
    REU -->|Sí| GR
    REU -->|No| KEEP[Permanece en la aplicación]
    AS --> KEEP
    KEEP --> CONT
    D --> LOAD[Carga selectiva según la tarea]
    A --> LOAD
    G --> LOAD
El estado, historial y decisiones de una aplicación se conservan para futuras versiones. Solo los patrones generales se resumen además en la memoria técnica global.

4. Flujo integrado completo

Desde un requerimiento hasta la integración en GitHub y la actualización de la memoria del desarrollo.

1. Recuperación de contexto

  1. Recibir solicitud
  2. Leer instrucciones generales
  3. Analizar repositorio
  4. Revisar aplicación, código y pruebas
  5. Consultar documentación
  6. Recuperar memoria relevante
  7. Leer estado actual

2. Análisis y decisión

  1. Analizar objetivo y restricciones
  2. Identificar tipo de desarrollo
  3. Proponer tecnología
  4. Seleccionar agente especialista
  5. Definir alcance, archivos y pruebas
¿Usuario confirma?
Si no, se ajusta el alcance.

3. Preparación

  1. Crear rama de trabajo
  2. Determinar ubicación
  3. Crear carpeta si es una aplicación nueva
  4. Crear README, memoria y pruebas base
  5. Conservar estructura si ya existe

4. Implementación

  1. Trabajar con el agente especialista
  2. Crear o modificar código
  3. Usar bibliotecas compartidas
  4. Crear o actualizar pruebas
  5. Ejecutar validaciones
Si hay errores, corregir y repetir las pruebas.

5. Registro e integración

  1. Revisión humana
  2. Actualizar versión y CHANGELOG
  3. Actualizar estado, funcionalidades y pendientes
  4. Registrar dependencias, errores y pruebas
  5. Crear Pull Request
  6. Integrar en la rama principal
La memoria de la aplicación se actualiza siempre. Lo reutilizable pasa a la memoria técnica general.
La memoria de la aplicación se actualiza siempre al terminar un desarrollo. La memoria técnica general recibe únicamente conocimiento que pueda servir a otras herramientas o proyectos.
